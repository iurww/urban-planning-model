# 使用指南：数据合成与训练

所有命令都在项目根目录执行。统一数据入口为：

```bash
uv run up-model-data <subcommand> [args...]
```

训练入口为：

```bash
uv run up-model-train [args...]
```

## 1. 环境与前置条件

```bash
uv sync
uv run up-model-data --help
uv run up-model-train --help
```

外部依赖：

| 组件 | 用途 | 快速检查 |
|---|---|---|
| geofabrik离线下载`.osm.pbf` | OSM 清洗，不在运行时联网下载 | `ls data/pbf/*.osm.pbf` |
| Gurobi + license | 三类静态专家解 | `uv run python -c 'import gurobipy; print(gurobipy.gurobi.version())'` |
| `eclipse-sumo` Python 包 | `netconvert`、SUMO、TraCI | `uv run python -c 'import sumo; print(sumo.SUMO_HOME)'` |

## 2. 目录结构

每套数据集有一个独立的 `<dataset-root>`。它可以是正式数据目录 `data/`，也可以是
验证数据目录 `datadoc/`。候选拓扑目录、SFT/PPO/Test 链接和选择 CSV 必须属于同一个
数据集根，不能跨根读取：

```text
<dataset-root>/
  <candidate-dir>/<tile>/evidence/      # OSM 清洗证据，不进入训练
  <candidate-dir>/<tile>/abstract/      # 候选拓扑与交通契约
  topology_selection.csv                # sft/ppo/test 选择表
  topology_selection.split_report.json
  sft/<tile> -> ../<candidate-dir>/...   # SFT 相对符号链接
  ppo/<tile> -> ../<candidate-dir>/...   # PPO 相对符号链接
  test/<tile> -> ../<candidate-dir>/...  # Test 相对符号链接
```

正式数据对应 `<dataset-root>=data`、`<candidate-dir>=final`；当前验证数据对应
`<dataset-root>=datadoc`、`<candidate-dir>=testdoc`。

#### 3.1.1 如何填写 `--crs`

选择以米为单位、覆盖目标城市的投影坐标系；不能填写 `EPSG:4326` 之类的经纬度坐标系。

城市级数据通常使用 WGS84 / UTM。给定城市中心经度 `lon` 和纬度 `lat`，UTM分区及 EPSG 编号为：

```text
zone = floor((lon + 180) / 6) + 1
北半球：EPSG = 32600 + zone
南半球：EPSG = 32700 + zone
```

天津中心点为`(lon, lat) = (117.3616, 39.3434)`。其经度位于 UTM 50N（东经 114°–120°），因此使用 `EPSG:32650`。

#### 3.1.2 如何计算 `--col-range` 和 `--row-range`

设 tile 边长为 `S = --size-m`，网格原点为`(Ox, Oy) = (--origin-x, --origin-y)`。列号 `c`、行号 `r` 对应 tile 的投影边界为：

```text
xmin = Ox + c * S          xmax = Ox + (c + 1) * S
ymin = Oy + r * S          ymax = Oy + (r + 1) * S
```

`--col-range C0 C1` 和 `--row-range R0 R1` 都是左闭右开的整数区间，实际枚举`c ∈ [C0, C1)`、`r ∈ [R0, R1)`，总 tile 数为`(C1 - C0) * (R1 - R0)`。修改 CRS、原点或边长都会改变行列号和网格边界；同一区域分批生成时必须复用这三个参数。

下面的脚本从城市中心经纬度计算 UTM CRS，并生成中心附近 `12 × 12` 个 tile 的行列区间。`always_xy=True` 表示输入顺序固定为经度、纬度：

```bash
uv run python - <<'PY'
from math import floor

from pyproj import Transformer

lon, lat = 117.3616, 39.3434
size_m = 4000
origin_x, origin_y = 0, 0
num_cols, num_rows = 12, 12

zone = min(60, max(1, floor((lon + 180) / 6) + 1))
epsg = (32600 if lat >= 0 else 32700) + zone
crs = f"EPSG:{epsg}"
x, y = Transformer.from_crs(
    "EPSG:4326", crs, always_xy=True
).transform(lon, lat)

center_col = floor((x - origin_x) / size_m)
center_row = floor((y - origin_y) / size_m)
col_start = center_col - num_cols // 2
row_start = center_row - num_rows // 2
col_stop = col_start + num_cols
row_stop = row_start + num_rows

print("--crs", crs)
print("projected center:", f"x={x:.3f}", f"y={y:.3f}")
print("center tile:", center_col, center_row)
print("--col-range", col_start, col_stop)
print("--row-range", row_start, row_stop)
PY
```

## 4. 第二步：筛选 tile 并建立 SFT/PPO/Test 选择

`prepare-training-data` 读取 `batch-osm` 的结果，不复制或改写 `evidence/`、`topology.json` 或 `traffic_signals.json`。该命令依次执行：

1. 按 tile 尺寸、结构校验、parcels/roads/intersections/junctions 数量范围和交通契约过滤；
2. 检查 Land 面积配额是否存在整数可行解；
3. 从合格候选中自动选择形态匹配、区域不交叉的 SFT/Test 集合；
4. 将新条目追加到选择 CSV，并按 CSV 中的 `sft`、`ppo`、`test` 同步三个符号链接目录。

选择 CSV 采用只追加策略：已有行及其 split 始终保留，自动筛选结果只会增加此前不存在的 tile，不会删除或重新划分人工选择。默认链接同步会删除三个 split 目录中已经不在CSV 对应 split 下的旧符号链接，但不会删除 `data/final` 中的候选和专家文件。

### 4.1 命令示例

正式候选根使用完整候选目录 `data/final`。首次从空 CSV 建立 100 个训练候选和
20 个测试候选时，先 dry-run：

```bash
uv run up-model-data prepare-training-data \
  --data-root data/final \
  --train-count 100 --test-count 20 \
  --land-feasibility-time-limit 5 \
  --dry-run
```

`--dry-run` 会完成过滤、Land 可行性检查和划分计算，但不写 CSV、报告或符号链接。
确认结果后正式执行：

```bash
uv run up-model-data prepare-training-data \
  --data-root data/final \
  --train-count 100 --test-count 20 \
  --land-feasibility-time-limit 5
```

已有选择 CSV 时，可以只按其 `split` 列同步符号链接：

```bash
uv run up-model-data prepare-training-data \
  --data-root data/final \
  --from-csv data/topology_selection.csv
```

`--from-csv` 模式不扫描或筛选其他候选，不运行 Land 可行性检查和自动划分，也不生成或
改写 CSV、`topology_selection.split_report.json`。它只校验 CSV 中的已选 tile，同步
`sft`、`ppo`、`test` 符号链接，并刷新三个目录中的 `selection_manifest.json`。

### 4.2 参数

| 参数 | 默认 | 功能 |
|---|---:|---|
| `--data-root` | `data/final` | `batch-osm` 候选根 |
| `--selection-csv` | `<data-root>/../topology_selection.csv` | 带 `sft/ppo/test` 划分的选择表 |
| `--from-csv CSV` | 无 | 仅按指定 CSV 同步三个 split 的链接和 manifest，跳过其他操作 |
| `--link-output-root`, `--sft-link-output-root` | `<data-root>/../sft` | SFT 符号链接目录；两个参数名等价 |
| `--ppo-link-output-root` | `<data-root>/../ppo` | PPO 符号链接目录 |
| `--test-link-output-root` | `<data-root>/../test` | Test 符号链接目录 |
| `--train-count` | `80` | 本轮自动匹配的 SFT 数量；遗留参数名 |
| `--test-count` | `20` | 本轮自动匹配的 Test 数量；`train-count` 必须能被它整除 |
| `--tile-size-m` | `4000` | 要求的宽和高 |
| `--tile-size-tolerance-m` | `0.01` | 尺寸绝对容差（米） |
| `--min/max-parcels` | `30/110` | 地块数范围 |
| `--min/max-roads` | `30/150` | 道路数范围 |
| `--min/max-intersections` | `20/110` | 全部支撑交叉点数范围 |

| `--exclude-tile ID` | 无 | 排除已知下游失败 tile；可重复 |
| `--keep-unselected-links` | 否 | 不删除已不在 CSV 的旧链接 |
| `--dry-run` | 否 | 完成筛选和划分检查，但不写 CSV、报告或链接 |

### 4.3 产物

该命令生成：

- `data/topology_selection.csv`：字段为 `tile_id,city,topology_path,split`；
- `data/topology_selection.split_report.json`：过滤原因、可行性结果和划分统计；
- `data/sft/<tile>`、`data/ppo/<tile>`、`data/test/<tile>`：指向
  `data/final/<tile>/abstract/` 的相对符号链接；

程序取 `--data-root` 的父目录作为数据集根。当合格数量不足时报错，此时应扩大候选范围。

## 7. 第四步 B：SUMO OD 与 MaxPressure 专家

`sumo-collect-batch` 会对批量根下的每个 tile 依次生成 SUMO 路网和 OD，再运行MaxPressure 信号控制仿真。

每个 tile 的处理流程为：

1. 从 `traffic_signals.json.sumo_network` 生成 SUMO plain XML，并用 `netconvert`编译 `net.xml`。静态 bootstrap 先全红、再让每个 link slot 分别单独执行绿灯和黄灯，因此不依赖连接顺序且不会产生冲突；编译后再按照 from/to edge 和 lane 的完整连接身份，将契约中的灯态重排到 SUMO 实际 `linkIndex` 顺序；
2. 生成精确数量的合法 OD 路线。默认 50% 车辆从 boundary entry 前往 boundary exit，其余 50% 从全网有向边中选择起终点；所有路线均由 SUMO 路网求解，全部路线合计覆盖 100% 抽象道路。每辆车的出发速度由 `seed` 确定，先在起始边限速的`[0.05, 0.25)` 倍内采样，再按边长和制动能力限制到能在路口前安全停车的速度；
3. 运行固定 1200 秒、共 80 个 15 秒决策步。每个路口选择合法 canonical action 中pressure 最大的动作；动作改变时执行 3 秒当前相位 yellow，再执行 12 秒目标green；动作不变时保持原灯态 15 秒，不插入 yellow。

### 7.1 命令示例

正式数据的 SFT、PPO 和 Test 分别运行：

```bash
uv run up-model-data sumo-collect-batch \
  --topology-base data/sft \
  --workers 18 \
  --seed 0 \
  --vehicle-count 2000 \
  --depart-end 900 \
  --force

uv run up-model-data sumo-collect-batch \
  --topology-base data/ppo \
  --workers 18 \
  --seed 0 \
  --vehicle-count 2000 \
  --depart-end 900 \
  --force

uv run up-model-data sumo-collect-batch \
  --topology-base data/test \
  --workers 18 \
  --seed 0 \
  --vehicle-count 2000 \
  --depart-end 900 \
  --force
```

需要保证路网、OD 和轨迹全部按当前规则重建时使用 `--force`。后续断点续跑时去掉`--force` 并增加 `--skip-existing`；已有 `signal_trajectory.json` 的 tile 会被跳过：

```bash
uv run up-model-data sumo-collect-batch \
  --topology-base data/sft \
  --workers 5 \
  --seed 0 \
  --vehicle-count 2000 \
  --depart-end 900 \
  --skip-existing
```

可以用sumo-gui查看仿真结果

```bash
uv run up-model-data sumo-replay \
  data/sft/hangzhou_4km_c59_r841 \
  --delay-ms 100
```

### 7.2 参数

| 参数 | 默认 | 功能 |
|---|---:|---|
| `--topology-base PATH` | `data/train` | 批量根；正式运行时明确传入 `data/sft`、`data/ppo` 或 `data/test` |
| `--workers N` | `1` | 并行处理的 tile 数；批量使用 `sumo-gui` 时建议保持为 1 |
| `--limit N` | 无 | 按目录名排序后只处理前 N 个 tile，用于小规模验证 |
| `--seed N` | `0` | OD 路线选择和 SUMO 仿真的随机种子 |
| `--vehicle-count N` | `2000` | 每个 tile 的精确车辆数；数量过小、无法在固定 OD 配额内覆盖全部道路时失败 |
| `--depart-end SEC` | `300` | 计划发车时间窗上限；车辆均匀安排在 `[0, SEC)` 秒 |
| `--force` | 否 | 强制重新编译 SUMO 路网；未跳过的 tile 本轮都会重生成 OD 和专家轨迹 |
| `--skip-existing` | 否 | 已有 `signal_trajectory.json` 时跳过整个 tile |
| `--verbose` | 否 | 保留参数；当前不增加额外输出 |

### 7.3 产物

每个成功 tile 生成：

```text
<topology-base>/<tile>/
  sumo/
    network.nod.xml       # SUMO 节点 plain XML
    network.edg.xml       # 有向道路和车道 plain XML
    network.con.xml       # 车道转向连接 plain XML
    network.tll.xml       # 顺序无关的全红 + 单 link 绿/黄灯 bootstrap
    net.xml               # netconvert 编译后的可运行路网
    routes.xml            # 全部车辆、计划发车时刻和路线
    demand_manifest.json  # OD 类别、路线/道路覆盖与速度统计
  signal_meta.json        # 按 compiled linkIndex 重排后的运行控制合同
  signal_trajectory.json  # 固定 80 步的 MaxPressure 专家轨迹
```



## 8. 第五步：训练

SFT 使用 `data/sft`，PPO 使用 `data/ppo`，两个阶段都在固定的 `data/test` 上执行周期性测试。

### 8.1 全流程测试

Smoke test 直接读取 `src/configs/smoke_train.json` 中的模型、SFT、PPO、test、device 和 W&B 参数，命令行只负责切换阶段、数据池、输出目录和 PPO 初始化 checkpoint。

```bash
uv run up-model-train \
  --config src/configs/smoke_train.json \
  --output-dir outputs/smoke_sft

uv run up-model-train \
  --config src/configs/smoke_train.json \
  --stage ppo \
  --data-root data/ppo \
  --init-checkpoint outputs/smoke_sft/sft_best.pt \
  --output-dir outputs/smoke_ppo
```

### 8.2 全流程完整训练

第一条命令使用 `data/sft` 完成 SFT，成功后第二条命令自动使用 `data/ppo` 并从 `sft_best.pt` 启动 PPO；两个阶段共同使用配置中的 `data/test`。

```bash
uv run up-model-train \
  --config src/configs/train.json \
  --stage sft \
  --data-root data/sft \
  --device cuda:0 \
  --output-dir outputs/upmodel_sft \
  --wandb-mode online --wandb-name upmodel-sft \
  --fail-if-output-exists

uv run up-model-train \
  --config src/configs/train.json \
  --stage ppo \
  --data-root data/ppo \
  --init-checkpoint outputs/upmodel_sft/sft_best.pt \
  --device cuda:0 \
  --output-dir outputs/upmodel_ppo \
  --wandb-mode online --wandb-name upmodel-ppo \
  --fail-if-output-exists
```

#### 随机初始化

不传 `--init-checkpoint` ：

```bash
uv run up-model-train \
  --config src/configs/train.json \
  --stage ppo \
  --data-root data/ppo \
  --device cuda:0 \
  --output-dir outputs/upmodel_ppo_random_init \
  --wandb-mode online --wandb-name upmodel-ppo-random-init \
  --fail-if-output-exists
```

`--init-checkpoint` 也可接 PPO 或其他同结构 checkpoint；

### 8.3 训练 CLI 参数

| `--sft-epochs` | 配置值 | 覆盖 SFT epochs |

| `--ppo-tasks` | 配置值 | 仅可选 `land road signal` |

| `--ppo-initial-logit-scale` | 配置值 | SFT actor 软化比例 `(0,1]` |

## 9. 第六步：独立最终评估

正式 test 报告使用 `up-model-eval`。`--fail-if-output-exists` 会在加载模型或运行 SUMO 前检查报告和 ledger 均不存在，避免覆盖已冻结结果：

```bash
uv run up-model-eval \
  --checkpoint outputs/upmodel_ppo/ppo_best.pt \
  --data-root data/test \
  --tasks land road signal \
  --episodes 1 --seed 0 --device cuda:0 \
  --output outputs/upmodel_ppo/formal_test.json \
  --fail-if-output-exists --wandb-mode disabled
```

| 参数 | 默认 | 功能 |
|---|---:|---|
| `--checkpoint` | 必需 | checkpoint；模型结构从其中的 config 恢复 |
| `--data-root` | `data/final` | 评估 tile 根；正式运行应显式传 `data/test` |
| `--tile-ids ID...` | 全部 | 只评估指定 tile |
| `--tasks` | 三个训练任务 | `land road signal` 的任意子集 |
| `--episodes` | `1` | 每 task/tile episode 数 |
| `--stochastic` | 否 | 使用采样策略；默认 greedy |
| `--seed` | `0` | SUMO seed；0 与现有专家轨迹对齐 |
| `--device` | `auto` | PyTorch device |
| `--output` | `outputs/upmodel/evaluation.json` | 报告 JSON |
| `--fail-if-output-exists` | 否 | 报告或 ledger 已存在时拒绝运行 |
| `--wandb-mode/project/name` | disabled/配置值 | 可选独立 W&B 评估 run |
| `--log-level` | `INFO` | 日志级别 |
